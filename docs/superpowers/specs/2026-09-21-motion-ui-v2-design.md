# 교정 진행 영상 도구 화면 개편(v2) 설계

작성일: 2026-09-21
상태: 구현 완료, 공개 대기 (2026-09-21)
바탕: [2026-09-20-motion-tool-design.md](2026-09-20-motion-tool-design.md) — 부품(load/orient/align/color/interp/encode)은 그대로 두고 **화면(motion/index.html, main.js)만** 다시 짠다.

## 1. 왜

원장이 진료실에서 써 본 소감: 화면을 꽉 채우지 못하고(폭 1100px 흰 양식), 사진 넣는 자리가 다른 도구와 달리 위에 있으며, MP4 저장 버튼이 눈에 안 띈다. CaseFrame 본체·선그리기와 같은 화면 문법으로 통일한다.

## 2. 화면 문법 (선그리기 `line/index.html`을 기준으로 옮긴다)

- **검은 바탕**, 색 토큰 그대로: `--bg:#000; --panel:#121A22; --panel-2:#18222C; --line:#273240; --muted:#93A1B0; --text:#E8EEF4; --accent:#35C7B0; --accent-2:#1E9B84`. 글꼴 `Inter, Pretendard, "Noto Sans KR", system-ui`. 화면 전체(100vh, overflow hidden), 폭 제한 없음.
- **위쪽 막대(topbar)**: 로고+"CaseFrame / 교정 진행 영상 · 로고를 누르면 처음으로"(선그리기 `.brand` 마크업 복사), 개인정보 문구(`.privacy-note` "사진은 이 컴퓨터 안에서만 처리됩니다"), `전체화면(F)` 버튼, 오른쪽 끝에 **주 버튼 하나**: 상태에 따라 `영상 만들기` ↔ `MP4 저장`(§4).
- **작업 영역(workspace)**: 왼쪽 기둥 없음(도구가 하나뿐이라 불필요). 가운데 **큰 판(stage)** + 오른쪽 **조절판(inspector, 280px)**.
  - stage(영상 전): 사진들을 격자로 크게 펼침(한 장 최소 220px 폭, 창 크기에 따라 열 수 자동). 각 사진 위에 번호·날짜 배지, 경고 배지(§3). 사진이 없으면 가운데 안내판(`.sheet-empty` 스타일): "같은 방향 교정 사진을 아래 칸이나 이 화면에 끌어다 놓으세요".
  - stage(영상 후): 영상이 판을 꽉 채워 재생(controls). 영상 아래 줄에 `MP4 저장`(주 버튼과 같은 모양) · `다시 만들기` · `사진 전부 비우기`.
  - inspector: ① 설정(품질 고품질/빠르게, 한 단계 시간 0.5~2.0초, 경과 글씨) ② 진행(막대, 단계 글씨, **남은 시간 약 N분**, 취소 버튼) ③ 결과 정보(길이, 크기, 파일 이름) ④ 도움말 4줄(촬영 팁 포함).
- **아래 사진 줄(filmstrip)**: 선그리기와 같은 구성 — 왼쪽 `film-info`(제목 "가져온 사진", 설명, `폴더에서 선택` 버튼, hidden file input) + 가로 스크롤 `asset-list`(작은 그림 100px 높이, 번호, 뒤집기·빼기 버튼, 끌어서 순서 바꾸기, 잠금 시 흐리게) + `film-hint` 2줄.
- **전체 화면 끌어놓기**: `#drop{position:fixed;inset:0}` 점선 덮개(선그리기와 같음). 화면 어디에 떨어뜨려도 사진 추가.
- 알림은 `#toast`(선그리기와 같은 위치·모양). 오류·취소·저장됨 안내를 여기로.

## 3. 배지와 표시

- 자동 뒤집음: 노란 배지 "자동 뒤집음" (테두리 색 + 글씨 둘 다). 다른 방향?: 빨간 배지. 구도 실패: 회색 배지 "구도 실패".
- 진행 중: 사진 줄과 격자의 조작 버튼 잠금(흐리게), 설정 잠금. 남은 시간 = (경과 시간 / 처리한 프레임) × 남은 프레임, 10초마다 갱신, "약 N분 M초".

## 4. 주 버튼과 저장

- 위쪽 막대 오른쪽 끝의 주 버튼(`.btn.primary`, 선그리기 저장 버튼보다 한 단계 크게: 높이 36px, 글씨 14px 굵게).
  - 사진 2장 미만: 비활성 "영상 만들기".
  - 준비됨: "영상 만들기". 만드는 중: "만드는 중 …%"(비활성) + 취소는 조절판.
  - 완성: **"MP4 저장"**으로 바뀌며 0.8초간 두 번 부드럽게 밝아지는 애니메이션(`@keyframes pulse`)으로 시선을 끈다. 같은 버튼이 stage 영상 아래에 하나 더.
  - 저장을 누르면 토스트 "저장됨: <파일 이름>".
- **파일 이름**: `<첫 사진 첫 토막>_교정진행_<품질>_<YYYY-MM-DD>.mp4`. 품질 = `고품질` / `빠르게` / `단순`(인공지능이 안 돌아 단순 겹치기로 만든 경우). 날짜 = 만든 날(컴퓨터 시계). `encode.outputName(firstName, ext, quality, date)`로 바꾼다(기존 2인자 호출은 없음 — main.js만 씀).

## 5. 첫 화면 버튼

- `index.html`의 `/motion/` 버튼 아이콘을 전용 SVG로: 작은 사진 틀 3장이 겹쳐 있고 오른쪽에 재생 삼각형(청록). 클래스 `sg-motion` 새로 추가(`sg-line` 빌려 쓰지 않음).

## 6. 하지 않는 것

- 부품 알고리즘 변경 없음(orient/align/color/interp의 계산은 그대로).
- 기본 품질·계산량(planTiming)은 그대로 — 원장 실측 후 별도 결정.
- 모바일 전용 레이아웃은 만들지 않음(선그리기와 같이 좁은 화면에서는 세로로 쌓이기만 하면 됨).

## 7. 검사

1. 브라우저(크롬): 25장 넣기 → 격자 표시·배지 → 만들기 → 진행/남은 시간 → 완성 시 주 버튼이 "MP4 저장"으로 바뀌고 깜빡임 → 저장 파일 이름 `임희진_교정진행_고품질_2026-09-21.mp4`.
2. 창 폭 1280·1920에서 판이 꽉 차는지, 900px 이하에서 조절판이 아래로 내려가는지.
3. 화면 아무 곳에 사진 떨어뜨리기, 사진 줄에서 순서 바꾸기·뒤집기·빼기, 진행 중 잠금, 취소.
4. `node --test 'motion/test/*.test.mjs'` 전부 통과(outputName 시험 갱신).
