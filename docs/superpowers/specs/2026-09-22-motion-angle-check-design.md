# 교정 진행 영상 도구 — 각도 검사(이웃 겹침 점수) 설계

작성일: 2026-09-22
상태: 원장 승인 (설계 단계)
바탕: [2026-09-22-motion-ui-v3-design.md](2026-09-22-motion-ui-v3-design.md). 바꾸는 파일: `motion/js/main.js`, `motion/index.html`, `motion/js/align.js`(점수 함수 추가), `motion/test/align.test.mjs`, `motion/README.md`.

## 1. 왜

각도가 크게 다른 사진이 섞이면 영상이 어른거린다. 자동 원근 보정은 실험 결과 도움이 안 됐다(2026-09-22 실험, 24쌍 중 6쌍만 미미하게 개선). 대신 **"이웃과 잘 안 겹치는 사진"을 표시해 원장이 빼도록** 한다. 표시만 하고 결정은 사용자가 한다(각도 차이와 실제 치아 이동을 완벽히 구분하지 못하므로).

## 2. 점수

- 구도 맞추기(`chainTransforms` + `warpImage`) 결과에서 각 사진을 640×427로 줄이고 7×7 블러, 가장자리(위아래 60·좌우 80px)를 잘라 정규화한 뒤, 이웃(앞·뒤)과의 정규화 상관 평균 = **겹침 점수**(0~1). 맥 파이썬과 같은 정의.
- `align.js`에 `neighborScores(cv, images: ImageData[]) → number[]` 추가(입력은 이미 기준 틀로 옮긴 사진들). 사진 2장이면 둘 다 같은 점수.
- 기준: `점수 < 0.75 × 중앙값` 이면 "이웃과 많이 다름". 사진 3장 미만이면 검사하지 않는다(안내만).

## 3. 화면

- 조절판 설정 아래(만들기 버튼 위)에 **`#checkBtn` "각도 검사"** 버튼(폭 100%, 높이 40px, 보통 버튼 색). 사진 3장 이상일 때만 활성. 누르면 잠금 + 진행("구도 맞추는 중 i/n" → "겹침 점수 계산 중") + 취소 가능.
- 끝나면: 기준 아래 사진의 격자 카드·사진 줄에 **주황 배지 "이웃과 많이 다름"**(`.badge.angle`), `title`에 "겹침 점수 0.53 (기준 0.52)". 토스트: "이웃과 많이 다른 사진 N장을 표시했습니다. 각도가 다르거나 간격이 긴 사진입니다. ✕로 빼면 영상이 매끄러워집니다." N=0이면 "모든 사진이 고르게 겹칩니다."
- 조절판 "진행" 아래에 작은 결과 줄 `#checkNote`: "각도 검사: N장 표시 (중앙값 0.70)" — 사진 편집(빼기·순서·뒤집기·추가)이 일어나면 배지와 이 줄을 지우고 "다시 검사하세요"로.
- 배지는 자동 뒤집음/다른 방향?/구도 실패 배지와 나란히(여러 개 가능).

## 4. 재활용

- 검사에서 얻은 `T`(변환)와 `status`, 그리고 기준 틀로 옮긴 사진(`aligned`)은 `state.cache = { key, T, status, aligned }`에 둔다. `key` = 사진 이름·순서·뒤집힘 상태를 이은 문자열.
- `make()`는 `state.cache.key`가 현재와 같으면 구도 맞추기를 건너뛰고 캐시를 쓴다(진행 막대는 그 구간을 즉시 채움). 다르면 기존대로 새로 계산한다.
- 메모리: `aligned` 25장 ≈ 140MB. 40장이면 ≈ 220MB — 허용. 사진이 바뀌면 캐시를 버린다.

## 5. 하지 않는 것

- 자동으로 빼지 않는다. 기준 조절 슬라이더는 두지 않는다(단순 유지).
- 원근 보정은 넣지 않는다.

## 6. 검사

1. Node: `neighborScores`에 합성 사진(같은 텍스처 4장 + 크게 다른 1장)으로 낮은 점수가 그 1장에만 나오는지.
2. 크롬: 25장 → 각도 검사 → 2025-11-24, 2023-06-26 등이 주황 배지 → ✕로 빼기 → 배지·결과 줄 초기화 → 다시 검사 → 영상 만들기가 구도 단계를 건너뛰는지(진행 글씨·시간).
3. 취소 중 검사 → 잠금 해제·배지 없음.
4. `node --test 'motion/test/*.test.mjs'` 통과.
